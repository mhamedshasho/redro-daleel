تجهيز Redro دليل

المشروع يعمل على Cloudflare Pages وPages Functions وD1. تخزين الصور R2 اختياري وغير مفعّل حالياً؛ بقية الدليل يجب أن تعمل دون R2، بينما رفع الصور سيبقى غير متاح.

1. ربط المشروع وقاعدة البيانات

  1. اربط مستودع mhamedshasho/redro-daleel بحساب Cloudflare Pages.
  2. فرع الإنتاج هو main ومجلد النشر public، مع إبقاء Pages Functions مفعّلة.
  3. اربط D1 باسم binding DB بقاعدة البيانات redro-daleel.
  4. تم تطبيق ترحيلات D1 من 0001 إلى 0005 على قاعدة البيانات المرتبطة. لا تعِد تطبيقها يدوياً دون التحقق من سجل الترحيلات.

2. إعداد مفاتيح الخدمات

أضف المتغيرات والأسرار من إعدادات Cloudflare Pages ضمن Production. لا تضع أي مفتاح سري في ملفات الموقع أو GitHub أو المحادثات.

  • ADMIN_API_KEY — Secret: أنشئ قيمة عشوائية طويلة واحفظها في مدير كلمات مرور. أدخل القيمة نفسها في نموذج الدخول إلى /admin.html.
  • GEMINI_API_KEY — Secret: أنشئ المفتاح من Google AI Studio ثم أضفه مباشرة إلى Cloudflare.
  • GEMINI_MODEL — Plain text: القيمة الحالية gemini-2.5-flash.
  • TURNSTILE_SECRET — Secret: أدخل المفتاح السري الخاص بموقع Turnstile المرتبط بنطاق redro-daleel.pages.dev.

إذا أردت استخدام روابط Preview لاختبار إرسال الطلبات، أضف أسرار Gemini وTurnstile وAdmin إلى إعدادات Preview أيضاً. لا تشارك قيم الأسرار مع أي شخص.

3. تخزين الصور

R2 غير مربوط حالياً بسبب متطلبات تفعيل الفوترة. لا تحتاج إلى R2 لتشغيل التصفح والبحث وإدارة البيانات الأساسية. رفع الصور وعرضها سيعيدان رسالة أن تخزين الصور غير متاح إلى أن يتم ربط R2 لاحقاً باسم binding IMAGES.

4. التحقق والدخول

  1. انتظر نجاح آخر نشر من فرع main.
  2. افتح /api/health وتحقق من حالة قاعدة البيانات والخدمات. لا تكشف الصفحة أي قيمة سرية.
  3. افتح /admin.html وأدخل قيمة ADMIN_API_KEY التي ضبطتها في Cloudflare.
  4. اختبر نموذج تقديم مشروع بعد التأكد من إعداد Gemini وTurnstile. لا يُنشر الطلب إذا تعذرت مراجعة Gemini؛ يُحفظ لإعادة المحاولة.

مهم: نجاح نشر Pages لا يثبت وحده أن كل الأسرار صحيحة أو أن إرسال الطلبات يعمل. يجب إجراء اختبار فعلي للـ API ونموذج الإرسال ولوحة الإدارة قبل اعتبار المشروع جاهزاً للإنتاج.
